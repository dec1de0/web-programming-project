# Архитектура BitRate

BitRate — синхронное FastAPI-приложение с тремя связанными ресурсами: **Project → Audit → Finding**. Отчёт вычисляется по аудиту и его замечаниям, отдельно не хранится.

## Слои

- `api/routes`: URL, параметры, HTTP-статусы и модели ответа.
- `schemas`: Pydantic-валидация запросов и структура ответов.
- `services`: правила проекта, анализа и изменения статуса замечаний.
- `models.py`: SQLAlchemy-модели Project, Audit, Finding; UUID, FK, UNIQUE и CHECK.
- `database.py`: DATABASE_URL, Engine и sessionmaker.
- `api/dependencies.py`: отдельная Session и транзакция на запрос.
- `alembic/`: воспроизводимая схема базы данных.
- `api/error_handlers.py`: перевод предметных ошибок в 404/409/422.

Engine создаётся при запуске приложения и освобождается при завершении.
Зависимость get_session открывает Session и транзакцию: успешный запрос получает commit,
ошибка — rollback, соединение всегда возвращается в пул. scope="function" завершает
транзакцию до отправки HTTP-ответа. Сервисы используют flush, но не commit.
Разные экземпляры приложения с одинаковым DATABASE_URL видят одни данные.

Project 1 → N Audit, Audit 1 → N Finding. PostgreSQL выполняет ON DELETE CASCADE.
Имена проектов нормализуются Python casefold в name_key с UNIQUE; это сохраняет прежнее
правило и защищает от конкурентных дублей. FK запрещают осиротевшие записи; CHECK
ограничивает оценки, типы и статусы, требует комментарий для resolved.
FOR UPDATE сериализует изменения одного проекта/finding и создание аудита с удалением
родителя. Нарушение ограничений превращается в 409 без раскрытия SQL или credentials.
Схема создаётся только через Alembic, прежние данные из памяти автоматически не переносятся.

## Три сценария

1. **Проект:** создать, найти, переименовать, удалить. Имена уникальны без учёта регистра; удаление каскадно удаляет аудиты и замечания.
2. **Аудит:** выбрать существующий проект, отправить Python-текст или характеристики элементов интерфейса. Анализ выполняется без запуска кода; аудит и замечания записываются вместе. Повторные аудиты создают историю.
3. **Замечания и отчёт:** фильтровать проблемы, закрывать их с комментарием, открывать повторно и смотреть начальную и текущую оценки. Повторная установка того же статуса даёт 409.

Оценка: `max(0, 100 - сумма штрафов)`; low=5, medium=10, high=20, critical=30. Начальная оценка считает все замечания, текущая — только открытые. Ручное закрытие не меняет исходный результат аудита.

Границы версии: нет авторизации, frontend, загрузки Git-репозиториев, URL или внешнего AI. Дизайн проверяется только по переданным свойствам элементов.
