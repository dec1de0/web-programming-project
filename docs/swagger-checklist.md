# План ручной проверки через /docs

Сейчас это список будущих проверок, а не отчёт об их прохождении.
Для каждого реализованного endpoint проверить статус и тело ответа.

- [ ] GET /health → 200; Swagger и OpenAPI доступны.
- [ ] Создать проект → 201; получить по ID и в списке → 200.
- [ ] Пустое/слишком длинное имя, лишнее поле → 422.
- [ ] Повтор имени с другим регистром или пробелами → 409.
- [ ] PATCH проекта: корректное изменение → 200; пустое тело/null → 422.
- [ ] Поиск, offset/limit: корректные страницы; неверные границы → 422.
- [ ] Несуществующий UUID → 404; некорректный UUID → 422.
- [ ] Code-аудит: хороший и проблемный код, синтаксическая ошибка.
- [ ] Design-аудит: корректные элементы и элементы с нарушениями.
- [ ] Неверный kind, отсутствующие поля, превышение лимитов → 422.
- [ ] Аудит несуществующего проекта → 404, данные не создаются.
- [ ] История аудитов и фильтр kind, включая пустую историю → 200.
- [ ] Получение аудита и отчёта: существующий → 200, неизвестный → 404.
- [ ] Findings: фильтры severity/status, пагинация и пустой результат.
- [ ] Закрыть finding с комментарием → 200; без комментария → 422.
- [ ] Повторить текущий статус → 409; открыть снова → 200.
- [ ] Finding чужого аудита и несуществующий finding → 404.
- [ ] Проверить исходный и расчётный баллы отчёта после переходов статуса.
- [ ] DELETE проекта → 204, пустое тело; повторное удаление → 404.
- [ ] После удаления проекта его аудиты, отчёты и findings → 404.
- [ ] Перезапустить приложение: данные очищаются.
- [ ] Во всех сценариях отсутствуют необработанные исключения/HTTP 500.

Перед сдачей сохранить фактические результаты проверки и версии зависимостей.
