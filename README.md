# BitRate

Учебный проект по Web Programming Fundamentals, команда из трёх студентов.
REST API для раздельной оценки качества кода/безопасности и frontend-дизайна/UI/UX.

## Текущий статус

Подготовлен архитектурный каркас. Работают `/health`, `/docs` и `/openapi.json`.
Предметные endpoints, хранилище и анализаторы пока **не реализованы**;
файлы с TODO обозначают места дальнейшей реализации. Это ещё не готовая сдача.

## Запуск

Python 3.10+; команды выполняются из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m uvicorn app.main:app --reload
```

Swagger UI: http://127.0.0.1:8000/docs

## Структура

```text
app/
  main.py                 # Создание приложения, подключение роутеров
  errors.py               # Ошибки предметной области
  api/
    router.py             # Префикс /api/v1
    dependencies.py       # Получение store и сервисов
    error_handlers.py     # Преобразование ошибок в HTTP
    routes/               # health, projects, audits, findings
  schemas/                # Pydantic: запросы и ответы
  services/               # Правила, анализаторы, отчёты
  repositories/memory.py  # Хранилище в памяти
docs/
  architecture.md         # Сценарии, API, ограничения
  swagger-checklist.md    # План ручной проверки
tests/                    # Будущие регрессионные тесты
```

Поток вызова: **router → service → repository**. Анализаторы вызываются из сервисов.
Роутеры отвечают за HTTP, схемы — за форму данных, сервисы — за бизнес-правила.

## Распределение работы

1. Участник 1: проекты, хранилище, зависимости и целостность связей.
2. Участник 2: создание аудитов, анализаторы кода и дизайна.
3. Участник 3: найденные проблемы, отчёты и ручные проверки Swagger.

Сначала согласовать схемы и интерфейсы общего хранилища в команде.
План реализации: [архитектура](docs/architecture.md).
План проверки: [Swagger checklist](docs/swagger-checklist.md).

Данные будут храниться в памяти одного процесса и исчезать после перезапуска.
Для учебной версии запускать один worker. Проверки по правилам дают ограниченную
оценку и не гарантируют безопасность или удобство продукта.
